Engineering

Built like it has to last — because it does.

Internal tools get used every day for years. That means real infrastructure, not a prototype that falls over when the second person logs in.

  • A real database. Supabase — not a spreadsheet pretending, not data trapped in one browser.
  • Proper authentication. Accounts, roles and permissions, so the apprentice sees the job list and not the margins.
  • A deployment pipeline. GitHub and Vercel — every change reviewable, every change reversible.
  • Handover documentation. Written so another developer could pick it up. You're never locked in to me.

Common questions

Asked before, answered straight.

Which areas do you cover?

Telford and Shropshire, Wolverhampton, Birmingham and the wider West Midlands — see custom software across the West Midlands. Software work needs fewer site visits than a website, so distance across the region is not a constraint.

Do I own the software?

Yes. On full payment the code, the data and the deployment are yours. I keep my own pre-existing frameworks and libraries — that's standard, and it's part of what makes me fast — but the tool built for you belongs to you, and the handover documentation means another developer could take it on.

What does it cost to run after launch?

Usually very little. Tools this size typically run on hosting tiers costing a few pounds a month, in your own accounts, in your name. I set them up so the bills go to you and nothing routes through me.

How long does a build take?

A small tool is typically weeks, not months; a larger application is quoted with its own milestone dates. You get real dates in the written scope, and delivery is tracked against them — running projects to time is literally my profession.

What if we're not sure software is the answer?

That's what the Groundwork Visit is for. I map how the work actually flows, and if the honest answer is "you don't need software, you need a different spreadsheet," I'll say so in writing and you've spent a few hundred pounds to avoid wasting thousands.

Can you take over a tool someone else built?

Sometimes. I'll review it first — honestly. If it's salvageable I'll quote for taking it on; if rebuilding is genuinely cheaper than rescuing, I'll show you why rather than billing you to find out.
